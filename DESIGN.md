# Архитектура и дизайн проекта «Bulls and Cows»

## 1. Структуры данных и алгоритмы

### Состояние игры и история попыток

Для хранения состояния используется иммутабельный объект `GameState` (описан в `src/types.ts`), который содержит:

- `config` (настройки раунда: длина и база).
- `secret` (строка с загаданным числом).
- `attempts` (массив объектов `Attempt` — история ходов).
- `status` (текущий статус игры: `"playing"` или `"won"`).

**Почему так:**
Секретное число хранится в виде строки, чтобы корректно обрабатывать лидирующие нули (например, `"0123"`).
История попыток представлена массивом. При добавлении новой попытки (функция `addAttempt` в `src/state.ts`) используется спред-оператор `[...state.attempts, newEntry]`. Это обеспечивает иммутабельность: создается новый объект состояния, а старый массив не мутируется (никаких `push`). Это позволяет легко отслеживать изменения и избегать побочных эффектов.

### Алгоритм `evaluateGuess` (Быки и Коровы)

Реализован в `src/evaluateGuess.ts` с использованием функций высшего порядка (HOF):

1. Обе строки (секрет и попытка) приводятся к массивам символов и нижнему регистру (для поддержки hex).
2. **Быки:** считаются через `reduce`, который сравнивает символы на одинаковых индексах.
3. **Коровы:** сначала мы отфильтровываем символы, которые уже стали быками (чтобы избежать двойного счета). Затем для каждого оставшегося символа попытки проверяем его наличие в оставшейся части секрета через `includes` (или `filter`).

### Алгоритм `countPossibleSecrets` (Комбинаторика)

Реализован в `src/countPossibleSecrets.ts`.
Задача сводится к подсчету перестановок без повторений: \( P(base, length) = \frac{base!}{(base - length)!} \).
Алгоритм реализован рекурсивно: `count(len, base) = base * count(len - 1, base - 1)`.
Базовый случай рекурсии: если `length === 0`, возвращается `1`. Если `length > base`, возвращается `0`.
Для оптимизации применена **мемоизация** с помощью собственной HOF-функции `memoize` (`src/memoize.ts`), которая кэширует результаты в `Map`. Это предотвращает повторные вычисления при каждом открытии экрана настроек.

## 2. Оценка сложности (Big O)

- **`generateSecret(length, base)`**:
  - **Время: O(length)**. Мы выбираем ровно `length` символов. Благодаря алгоритму «вытягивания из мешка» (когда выбранный символ удаляется из доступного массива через `filter`), исключены коллизии и повторные попытки генерации.
  - **Память: O(base)**, так как мы создаем массив доступных символов.

- **`evaluateGuess(secret, guess)`**:
  - **Время: O(N²)**, где N — длина строки. Нахождение быков занимает O(N). Поиск коров в худшем случае требует O(N) для каждого оставшегося символа (из-за метода `includes`). Так как N в игре не превышает 6, это не является узким местом.
  - **Память: O(N)** для хранения массивов символов.

- **`isValidGuess(guess, length, base)`**:
  - **Время: O(N)**, где N — длина строки. Мы проходим по строке один раз для проверки допустимых символов (через `every`) и один раз для проверки уникальности (через `Set`).
  - **Память: O(N)** для создания `Set`.

- **`countPossibleSecrets(length, base)`**:
  - **Время: O(length)** благодаря мемоизации. Без мемоизации в худшем случае было бы O(length!) при наивном вычислении факториалов.
  - **Память: O(length)** для хранения кэша ключей в `Map`.

## 3. Принципы чистого кода (Clean Code)

В проекте применены следующие принципы, с указанием конкретных мест:

1. **Чистые функции (Pure Functions)**:
   - В `src/generateSecret.ts` источник случайности `random` передается аргументом (по умолчанию `Math.random`), а не вызывается внутри функции. Это делает функцию детерминированной и легко тестируемой.
2. **Иммутабельность (Immutability)**:
   - В `src/state.ts` функция `addAttempt` создает новое состояние с помощью спреда `{ ...state, attempts: [...state.attempts, newAttempt] }`. Мутации исходного объекта не происходит.
3. **Функции высшего порядка (HOF)**:
   - В `src/memoize.ts` реализована функция `memoize`, которая принимает другую функцию и возвращает ее обертку с кэшем.
   - В `src/evaluateGuess.ts` активно используются методы массивов `reduce`, `filter`, `map` вместо циклов `for`.
4. **Каррирование (Currying)**:
   - В `src/createDigitValidator.ts` фабрика `createDigitValidator(base)` возвращает функцию-предикат `(char) => boolean`. Это позволяет переиспользовать валидатор в `isValidGuess` и в живом фильтре поля ввода в `src/ui/gameScreen.ts`.
5. **Разделение ответственности (Separation of Concerns)**:
   - Вся бизнес-логика (в корне `src/`) не зависит от DOM и может быть запущена в Node.js.
   - UI-слой (`src/ui/`) только отрисовывает элементы и вызывает колбэки, не зная деталей реализации игры.
   - `src/main.ts` выступает в роли контроллера (дирижера), связывая логику и интерфейс.
6. **Безопасность и отсутствие `innerHTML`**:
   - Весь UI собирается через `document.createElement` и `textContent`. Это исключает риск XSS-атак и соответствует требованиям задания.
